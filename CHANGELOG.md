# Changelog

Все заметные изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [Unreleased]

## [1.8.0] — 2026-10-30

### Изменено

- Телеметрия: событие `tool_call` теперь отправляется по завершении вызова и несёт его исход: `ok`
  или категорию ошибки (`error_auth`, `error_invalid_request` и т. д.). При ошибке к нему
  добавляется фрагмент текста ошибки до 200 символов: HTTP-статус, код и сообщение API, текст
  отказа самого сервера или тип и первая строка ошибки в его коде. E-mail, адреса, токены, числа
  от 4 цифр и текст в кавычках заменяются на «#». Если в тексте ошибки есть значение из запроса,
  оно тоже может попасть во фрагмент. Отключение прежнее: `ASKADS_TELEMETRY=0`.

### Исправлено

- Телеметрия не может изменить результат вызова: если разбор исхода падает, клиент получает ровно
  то, что вернул инструмент.

## [1.7.0] — 2026-10-26

### Добавлено

- `upload_image`: загрузка JPEG/PNG в медиатеку (multipart `v2/content/static.json`) — base64 и
  размеры картинки, в ответе `id` и `variants`. Раньше объявление с картинкой было не создать: `content`
  требует id медиа, а `raw_request` отправляет только JSON. Формат проверяется по байтам, некорректный
  base64 и префикс `data:` отклоняются до запроса.
- `create_ad_plan`: параметр `adGroups` для первых групп кампании. Раньше обязательные группы жили только
  в `extra.campaigns`, и имя поля модель узнавала из описания; `extra.campaigns` и `extra.ad_groups`
  остаются синонимами. Группы с `id`/`ad_plan_id` и передача групп двумя способами отклоняются до запроса.

### Исправлено

- `create_banner` слал POST в `v2/banners.json` — это список объявлений. Теперь объявление создаётся в
  `v2/ad_groups/{adGroupId}/banners.json`; проверено вживую на заблокированных объектах.
- Общий и дневной бюджет в одном объекте VK отклоняет. Отказ до запроса был только на верхнем уровне
  `create_ad_plan`; теперь он срабатывает в create/update кампаний и групп, во вложенных группах и для
  бюджета из `extra` (`null`, сбрасывающий бюджет, не в счёт).

### Изменено

- Описания: `ad_plan_action delete` удаляет только кампанию — её группы и объявления остаются, их удаляют
  отдельно; картинка должна подходить слоту по размеру (`image_600x600` — не шире 600 px, иначе `bad_width`);
  у `budgetLimitDay` указан минимум 300 ₽ по справке VK.

## [1.6.1] — 2026-10-22

### Исправлено

- `get_statistics` снова принимает `autoPaginate` вместе с `period: "day"` и в `summary` без дат.
  1.6.0 отвергал эту комбинацию, хотя до неё она работала: в этих режимах VK отдаёт все объекты
  одним ответом, и `autoPaginate` там ничего не меняет. Ошибкой остаются только `limit`, `offset`,
  `sortBy` и `order` — их VK вне `summary` с датами молча игнорирует.

## [1.6.0] — 2026-10-22

### Исправлено

- Ошибки валидации VK теряли подробности: от `{"error": {"code", "message", "fields"}}` оставались
  только код и сообщение, и любая неудача выглядела как голое `Validation failed` (#14). Теперь в
  тексте ошибки есть `fields` — поле и причина, включая вложенные ошибки по группам — и
  `request_id` из `x-request-id`, который спрашивает поддержка VK.
- `get_statistics` по умолчанию отвечал 404: в v3 нет группировки `summary`, есть только
  `day.json`, и он отдаёт итог за период по каждому объекту (без строк по дням), с сортировкой и
  пагинацией. Теперь `summary` с датами идёт в v3 `day.json`, `summary` без дат — в v2
  `summary.json` (итог за всё время), `day` — в v2 `day.json` (строки по дням).

### Изменено

- `create_ad_plan` описывает контракт создания, проверенный на живом кабинете: нужна хотя бы
  одна группа в `extra.campaigns`, у кампании на сайт — `ad_object_type: "url"` +
  `ad_object_id` (без них любой `package_id` отвергается как `invalid_package`), для `max_goals` —
  `priced_goal` у группы. Кампанию без групп и `budgetLimit` вместе с `budgetLimitDay` инструмент
  отвергает сам, не тратя запрос.
- `get_statistics`: группировки `week` и `month` убраны — их нет ни в v2, ни в v3. Сортировка и
  пагинация вне `summary` с датами — ошибка, а не молча проигнорированный параметр. При
  `autoPaginate` поле `total` не возвращается: VK считает его только по последней странице.

## [1.5.1] — 2026-10-03

### Добавлено
- Плагин для каталога Anthropic (`plugin/`): манифест `.claude-plugin/plugin.json`, README, лицензия,
  иконка каталога и скилл `vk-ads-audit`. Плагин запускает опубликованный npm-пакет с точной версией
  и спрашивает креденшелы через `userConfig`, а не из окружения; телеметрия раскрыта в README и
  отключается в настройках плагина. Указана политика конфиденциальности.

### Изменено
- В пакет входит `npm-shrinkwrap.json`: ревью лаунчера каталога требует зафиксированных зависимостей.

## [1.5.0] — 2026-09-20

### Добавлено

- Вход в VK Рекламу прямо из диалога — тулы `start_login`, `finish_login`, `auth_status`, `logout`.
  `start_login` отдаёт инструкцию (создать приложение в кабинете: Настройки → Доступ к API),
  `finish_login` принимает `client_id` и `client_secret`, минтит токен (Client Credentials Grant)
  и кладёт его в `~/.config/mcp-vk-ads/credentials.json`. Браузерный `authorization_code` VK
  открывает только одобренным партнёрам с зарегистрированным redirect URI, поэтому пакету,
  который ставят через `npx`, остаётся минт по собственным ключам пользователя. `logout` стирает
  сохранённое с диска; токен на стороне VK не отзывается — `token/delete.json` убил бы ВСЕ токены
  этого пользователя для данного `client_id`.
- Автопродление токена. Токены VK живут ~24 ч; на 401 (`invalid_token`, `expired_token`,
  `revoked_token`) сервер один раз перевыпускает токен из `refresh_token` и повторяет запрос.
  Бюджет транспортных ретраев на это не тратится — он остаётся для сетевых сбоев.
- Событие телеметрии `unconfigured_start` с кодом причины: живой аналог `startup_failed` для
  установки, которая теперь переживает отсутствие токена. `server_start` сохраняет прежний смысл
  «стартовала рабочая установка», иначе воронка неподключённых раздувала бы его.

### Изменено

- Сервер больше не умирает без `VK_ADS_TOKEN`: он стартует неподключённым, проходит MCP-хендшейк
  и несёт причину в справке `initialize` — модель читает её до выбора тула и открывает сессию
  готовой инструкцией по подключению. Раньше процесс завершался ДО хендшейка, и пользователь
  видел красный крестик без единой строки объяснения; на этот сценарий приходилась почти вся
  воронка неподключённых установок.
- Токен резолвится на каждый запрос (env → сохранённые credentials), а не фиксируется в
  конструкторе клиента: `finish_login` действует со следующего же вызова, без перезапуска
  MCP-клиента. `VK_ADS_TOKEN` по-прежнему выигрывает у сохранённого — явная настройка и CI
  ведут себя как раньше.
- `VK_ADS_API_BASE` с не-http(s) значением теперь останавливает старт с кодом `invalid_api_base`:
  гадать, что имел в виду пользователь, хуже, чем сказать об ошибке.

## [1.4.2] — 2026-08-12

Отдельным релизом версия не выходила: тега `v1.4.2` нет, а изменения уехали в npm в
составе 1.5.0. Раздел оставлен, чтобы история была полной.

### Добавлено

- Инструкции сервера. В ответе MCP `initialize` теперь едет короткая справка для вызывающей
  модели: чем этот API является и чем не является, чего он не умеет, а также квоты, правила
  повторов и обманчивые ошибки, влияющие на то, как им пользоваться. Раньше это знание жило
  только в README, который модель не читает.
- Полная русификация текстов, которые видит пользователь: описания инструментов и их параметров,
  сообщения об ошибках, справка в ответе `initialize`, README и `docs/TOOLS.md`. Имена инструментов,
  параметров, полей ответа, значения перечислений и переменные окружения остались латиницей.

## [1.4.0] — 2026-08-07

### Добавлено
- Событие телеметрии `startup_failed`: сервер, умирающий из-за отсутствующих
  credentials, сообщает об этом до выхода — с машинным кодом причины
  (`missing_token`). Раньше такие установки не попадали в телеметрию
  вовсе:
  процесс завершался раньше MCP-хендшейка, и «не смог настроить» было
  неотличимо от «поставил и не пользуется». Отправляется только код —
  ни имя, ни значение переменной окружения; отключение прежнее:
  `ASKADS_TELEMETRY=0`.

### Изменено
- Конфигурация бросает `ConfigError` вместо немедленного `process.exit`, чтобы
  точка входа успела отправить пинг. Сообщение об ошибке и код возврата для
  пользователя не изменились; ожидание отправки ограничено прежними 2 с.

## [1.1.4] — 2026-07-02

### Безопасность
- `raw_request` / HTTP-клиент: SSRF-гард в `buildUrl` — абсолютный `path`
  (`https://…`, `http://…` или бэкслеш-форма `\\…`) больше не может перебить базовый
  origin и увести Bearer-токен на чужой хост; такой путь отклоняется до запроса.

### Исправлено
- Ретраи разделены по идемпотентности: 429 повторяется для любого метода (запрос не
  обработан), а 5xx **и сетевые ошибки/таймауты** — только для `GET`. Повтор `POST`
  после 502/504 больше не может создать дубль (`create_ad_plan/group/banner`).
- Таймаут запроса теперь покрывает и чтение тела ответа: `fetchWithTimeout` читает
  `res.text()` внутри охраняемой зоны и снимает таймер только после этого.

### Добавлено
- `autoPaginate`: кэп на размер ответа — не более `MAX_AUTO_ITEMS` (1000) объектов,
  лишнее обрезается с явной пометкой `_truncated` («returned the first N of M»).
- `get_regions`: кэш статичного справочника регионов (одна загрузка на процесс).
- `server.json`: описаны переменные `VK_ADS_TIMEOUT_MS` и `VK_ADS_MAX_RETRIES`.

### Изменено
- Вывод тулов — компактный JSON (без pretty-print) для экономии токенов; guard от
  `JSON.stringify(undefined)`.
- Аннотация `READ_ONLY` выставляет все четыре хинта
  (`readOnlyHint`/`destructiveHint`/`idempotentHint`/`openWorldHint`) — часть клиентов
  (напр. ревью OpenAI Apps) требует их на каждом туле.
- `isoDate` — фабрика (`isoDate()`), чтобы каждая схема получала свой zod-объект и в
  JSON-схеме не появлялся общий `$ref` (не все клиенты его разыменовывают).

### Удалено
- Мёртвый хелпер `clampLimit` (тулы ограничивают `limit` через zod `.max(250)`).

### Документация
- Требования и CI приведены к факту: Node.js 20+, матрица CI 20/22/24.

## [1.1.0] — 2026-06-24

### Добавлено
- MCP-аннотации (`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint`)
  на всех тулах — клиент MCP может авто-подтверждать чтение и предупреждать перед записью.

### Исправлено
- Сервер сообщает MCP-клиентам реальную версию из `package.json` (была захардкожена `1.0.0`).

### Изменено
- Публикуемый пакет уменьшен: чистка `dist/` перед сборкой, без source maps и `.d.ts`,
  dev-скрипт `smoke` исключён из сборки.

## [1.0.1] — 2026-06-18

### Изменено
- `get_statistics`: группировка `summary` по умолчанию (одна агрегированная строка на
  объект), серверная сортировка (`sortBy`/`order`) и «громкая» ошибка при фильтре по ids
  с нулём объектов вместо тихого пустого ответа.

## [1.0.0] — 2026-06-15

### Добавлено
- Первый релиз. MCP-сервер для VK Ads (VK Реклама): тулы для рекламных кампаний
  (`ad_plans`), групп (`ad_groups`) и объявлений (`banners`) — список/создание/обновление
  и lifecycle-действия (activate/stop/delete), статистика, справочники (регионы),
  `raw_request` (escape hatch на любой эндпойнт), пагинация (offset + авто по offset/count).
