# VK Реклама: Статистика — MCP-инструмент (tool)

**MCP-инструмент (tool) для VK Рекламы:** Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

Техническое имя: `get_statistics`

## Какую задачу решает

> Я хочу посмотреть статистику.

Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

## Когда использовать

Используйте эту возможность, когда нужен результат «Статистика» без ручной работы в интерфейсе VK Рекламы. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `entity` — **необязательно**. Тип объектов для отчёта. По умолчанию banners.
- `period` — **необязательно**. Группировка: summary (весь период, по умолчанию) либо day/week/month для динамики.
- `ids` — **необязательно**. Ограничить отчёт этими id объектов (выбранного entity).
- `dateFrom` — **необязательно**. Дата начала, YYYY-MM-DD (обязательна для day/week/month).
- `dateTo` — **необязательно**. Дата окончания, YYYY-MM-DD (обязательна для day/week/month).
- `metrics` — **необязательно**. Группы метрик в отчёте, например base, events, video. По умолчанию — набор API.
- `sortBy` — **необязательно**. Поле сортировки на стороне сервера, например base.spent / base.clicks / base.shows (топ-N по метрике).
- `order` — **необязательно**. Направление сортировки для sortBy. По умолчанию desc.
- `limit` — **необязательно**. Сколько объектов на страницу (не больше 250).
- `offset` — **необязательно**. Смещение постраничной выдачи (сколько объектов пропустить).
- `autoPaginate` — **необязательно**. Забрать все страницы, идя по offset/count.

## Что вернёт

Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

## Что изменится в VK Рекламе

Инструмент только читает данные или состояние подключения и не изменяет их.

## Пример запроса

> Посмотреть статистику в VK Рекламе. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

По умолчанию группировка `summary` — одна сводная строка на объект за весь период; day/week/month нужны ТОЛЬКО для динамики по дням и вопросов про тренд (каждая добавляет по строке на объект за период). Ранжирование на стороне сервера — через sortBy (например, base.spent) и order; в ответе есть также `total` — сводка по ВСЕМ объектам за период (для вопросов «сколько всего» суммировать строки не нужно). Метрики лежат в `base` (shows, clicks, spent, ...); spent — в валюте аккаунта.

Доступ также зависит от прав токена, квот и ограничений исходного API.

## Связанные MCP-инструменты

Связанных специализированных инструментов в этой группе нет.
